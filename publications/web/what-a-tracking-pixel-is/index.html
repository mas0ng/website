What a tracking pixel is

What a tracking pixel is, how those tiny images are used on pages and in email, and what they can record.

A tracking pixel is a tiny image, often a single transparent dot, whose only real job is to be requested. The request is the point. Loading it tells someone that a page, email, or advert was opened.

How a pixel works

An ordinary image tag asks the browser to fetch a file. If that file lives on a server that logs requests, the fetch itself becomes a signal:

  • the image was loaded
  • at this time
  • from this IP address
  • perhaps with a unique address in the image URL

The file can be 1×1 pixel, invisible, and cached or deliberately not cached. Emails use the same trick: many clients load remote images, and that load can report that the message was opened.

A pixel is not magic. It is a request for a resource, dressed up as a picture. Scripts, fonts, and other third-party files can do the same job without being called pixels.

Where they show up

  • advertising and conversion measurement on websites
  • email open tracking
  • “this page was viewed” beacons in analytics
  • social or marketing tags embedded in a page

First-party pixels report back to the site you are actually visiting. Third-party pixels report to someone else, which is how the same company can notice you on more than one site. That is the same distinction as first-party and third-party cookies.

What a pixel can record

By itself, a pixel proves little more than “this address was requested”. In practice it is combined with other signals: a unique code in the URL, cookies set when the image is fetched, the page you were on, and device information.

An email pixel can suggest that a message was opened. It cannot prove a human read it. A preview pane, a security scanner, or an image-loading proxy can fetch the file too.

Blocking images in email is an old, blunt defence. On the web, tracking-prevention features in browsers do more of that work now than users do by hand.

Pixels, cookies, and scripts

A pixel is one delivery method. The same organisation may also set a cookie, run a script, or use a larger analytics library. Clearing cookies does not always stop a pixel URL from being fetched. Blocking third-party cookies does not always block a third-party image.

If a page never loads the remote file, the pixel cannot fire. That is why some trackers wait for a script to run, then send a request that is not an image at all.
