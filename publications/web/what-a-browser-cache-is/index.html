What a browser cache is

What a browser cache is, why sites load faster on a second visit, and why you sometimes still see an old version of a page.

A browser cache is a local store of files the browser has already downloaded, so it does not have to fetch them again on the next visit. That is why a site often feels faster the second time.

What is being stored

A web page is not one file. It is a document plus stylesheets, scripts, fonts, and images. Many of those files change rarely. The cache keeps copies on the device and reuses them when the same URL is requested again.

The cache is not your account. It is not a cookie. It is not a password vault. It is a pile of recently used website files, with rules about how long they may be reused.

Cookies are small pieces of text a site asks the browser to send back later. The cache is the browser keeping copies of assets so the page can load without repeating the same downloads.

Why sites use it

Repeating the same downloads wastes time, battery, and bandwidth. Caching is the ordinary fix:

  • the first visit downloads the files
  • later visits reuse the copies that are still valid
  • only changed or expired files need to be fetched again

This happens on almost every public website. It is not tracking by itself. A cached logo does not tell a site what else you read.

Why you sometimes see an old page

Cached files are allowed to be reused for a limited time. If a site updates a file but your browser still has a valid copy, you can see yesterday's layout, an old image, or a script that no longer matches the HTML.

That is annoying and usually harmless. The usual remedies are:

  • a normal refresh, which may still reuse some files
  • a hard refresh, which asks for a fresh copy of the page
  • clearing cached images and files in the browser settings

Clearing the cache does not sign you out of every site by itself, but clearing “cookies and site data” often clears more than the cache. If you only wanted a stale page to update, clear cached files rather than everything.

Cache is not the same as other storage

People lump several browser stores together. They do different jobs:

  • Cache: copies of files, for speed
  • Cookies: small values sent back to the site
  • Local storage / session storage: data a page's own script reads, not sent automatically with every request

A site can use all of them. Blocking or clearing one does not always clear the others.

There are also caches you do not control directly: DNS caches, and caches operated by networks that deliver popular files. Those can also serve an old copy after a change.

Does caching affect privacy?

A cache lives on the device. Another site cannot simply open it and read everything you have visited. The browser does use it to decide whether it already has a file.

That is not a complete privacy picture. Cookies, fingerprinting, and the IP address of the request are separate issues. Caching is mostly a performance feature. Treat it that way unless a specific site has given you a reason not to.
