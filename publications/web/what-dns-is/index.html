What DNS is

A plain-language explanation of DNS, how a browser turns a domain name into an address, and why that lookup is not the same as encryption.

DNS is the system that turns a human-readable name such as example.com into the address a computer actually uses to reach a site. Without it, you would have to type numbers instead of names.

What DNS actually does

The Domain Name System is a directory. You ask for a name. It answers with records that say where that name currently points.

The most familiar answer is an address record: this name currently maps to this IP address. There are other record types too, for mail, aliases, and extra information about a domain. The important idea is the same. DNS is lookup, not the website itself.

A domain name is a label. The site, the server, and the DNS records can change independently. Buying a name does not magically create a page. Pointing the name at a service does not encrypt the later visit.

How a typical lookup works

When you type a web address, the browser needs somewhere to send the request. In outline:

  1. The browser checks whether it already knows the answer.
  2. If not, the computer asks a resolver, usually one provided by the network, ISP, or a chosen DNS service.
  3. That resolver may already have a cached answer. If not, it asks the wider DNS system, starting from the root and moving toward the name's own records.
  4. The answer comes back and is remembered for a short time.

You do not normally see those steps. A slow, failed, or hijacked lookup just looks like “the site will not load”.

Caching, TTL, and why changes take time

DNS answers are cached. Each record has a lifetime, often called TTL, that tells resolvers how long they may reuse the answer before asking again.

That is why a site move, a new subdomain, or a changed mail record can appear instantly for one person and take hours for another. Some devices, browsers, and networks keep their own copies. Flushing one cache does not flush every cache on the internet.

DNS is not encryption

A DNS lookup and an HTTPS page load are different jobs.

DNS finds where to send the request. HTTPS encrypts the later conversation with that destination. You can have one without the other.

Ordinary DNS queries are often visible to the resolver you use. Encrypted DNS options exist, but they change who can see the lookup. They do not hide the site from the site itself, and they do not make a destination trustworthy.

What can go wrong

  • A typing error or a lookalike domain can resolve perfectly and still be the wrong place.
  • A stale cache can send you to an old address after a site has moved.
  • A compromised or misleading resolver can point a real name at the wrong destination.
  • If DNS fails, the site may be up and still unreachable by name.

The padlock in the browser, when it appears, is about the connection that follows. It is not a verdict on the DNS path that got you there.
